# CHANGELOG — рішення й контекст, які не видно з коду одразу

Онови цей файл (і в GitHub, і в Project Knowledge), коли ухвалюєш
щось важливе поза межами звичайного "додав урок". Мета — щоб новий
чат у проєкті міг прочитати цей файл і зрозуміти контекст за хвилину,
а не гортати історію чатів.

## Дизайн
- Обрано "зошитовий" стиль (теплий папір/бірюза/теракота, компас,
  прогрес-літак) — два інші варіанти (підручниковий, грайливий)
  відхилені після порівняння прев'ю.

## Навчальна програма
- Теми модулів беруться з офіційного календарно-тематичного
  планування (PDF за 7/8/9 класи), не вигадуються довільно.
- **9 клас має лише 7 модулів**, не 8 — за програмою тем сім, восьма
  клітинка (`modules-data.js` → `H`) навмисно порожня.
- **7 клас, Модуль A** — офіційна тема "Я, моя родина, мої друзі";
  Урок 1 у цьому модулі — стандартний вступний урок-вікторина про
  Німеччину (спільний для кількох класів на початку року), а не
  контент про сімейні канікули.

## Структурні механізми
- Тема МОДУЛЯ живе окремо від уроків (`modules-data.js`), не в кожному
  уроці — можна проставити наперед, до появи самих уроків.
- Мітка "нове" — без дати. Показується на уроці, що стоїть ОСТАННІМ
  у масиві `LESSONS` для свого класу — тому нові записи завжди
  дописуються в кінець масиву, ніколи не вставляються в середину.
- Перевірка ДЗ — через поле `dz` в `lessons-data.js`: наступний урок
  модуля бере `dz` попереднього для вкладки "Hausaufgabe".
- Навігація (хедер + хлібні крихти) — один спільний `site-nav.js`,
  не дублюється по сторінках.

## Технічне
- Хостинг: GitHub Pages, файл `.nojekyll` у корені обов'язковий
  (без нього Jekyll іноді підміняє сайт дефолтним README).
- При завантаженні на GitHub — перетягувати ВМІСТ папки, а не саму
  папку (інакше все лягає на рівень глибше).

## Глосарій
- Сторінка `glosariy/` тепер сортує слова за абеткою (замість
  порядку додавання/уроків) і показує буквений покажчик угорі для
  швидкого переходу (клік по літері → скрол до групи слів на неї).
  Заголовки-літери над групами "прилипають" зверху при скролі.
- Сортування рахується за окремим ключем (`glossarySortKey` в
  `site.js`), який ігнорує артикль (`der`/`die`/`das`) і `sich` на
  початку слова — інакше майже всі іменники опинилися б під літерою
  "Д". Сам текст слова (`de`) в `glossary-data.js` не змінюється,
  ключ рахується на льоту при рендері.
- Фільтри за класом/модулем і пошук лишились без змін — сортування
  за абеткою застосовується ДО вже відфільтрованого списку.

## Робочі правила (для мене, Claude)
- Два окремі Project: "генерація уроків" і "технічна підтримка
  сайту". Частина файлів спільна для обох (README.md, CHANGELOG.md,
  STYLE-BRIEF.md, lesson-template.html, lesson-style.css,
  lesson-interactions.js, lessons-data.js, glossary-data.js,

  нагадую, що куди покласти** (GitHub / Knowledge цього проєкту /
  Knowledge іншого проєкту, якщо файл спільний). Це не одноразова
  ввічливість, а стандартна частина відповіді.
